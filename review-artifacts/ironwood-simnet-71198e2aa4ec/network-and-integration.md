## Peer, storage and wallet boundaries

* Proposed wire magic is `12 5d 56 63`, P2P port 28033 and authenticated loopback RPC port 28232. Use loopback by default. For multi-host runs use explicit consenting endpoints on a dedicated isolated lab subnet with deny-by-default egress and ingress. Drop public routes even for a misconfigured peer. Check the selected bind, effective routes and open peer set before minting.
* Stock testnet uses magic `fa 1a f9 bf`, P2P 18033 and seed `167.71.172.5`. The node also supports a per-user onion seed file. Start the experimental profile with empty DNS, fixed and onion seed lists, no default onion or public bootstrap, and no inherited connect/addnode flags, address database or onion peer directory. Disable address-based discovery, gossip-based connection expansion, automatic port mapping and public listeners. A mismatched-network negative handshake and an empty-allowlist zero-outbound check are prerequisites to a first shared run. Sources at the review base are `core/chainparams/src/chainparams.c:605` and `core/modules/net/src/connman_onion_seeds.c:496`.
* Use a fresh absolute lab root per node, e.g. `<lab-root>/zcl-iw-exp1/node-a/{home,config,data,state,cache}`, with owner-only directories and independent HOME/XDG paths. Put chainstate, peers, wallets, sockets and any lab Tor state beneath that root. Refuse a datadir containing a different manifest or existing network wallet. Never import existing wallets, seeds, keys, peers or chain databases. Use fresh synthetic keys and generated test coins only.
* Propose transparent Base58 address prefixes `30a1` (P2PKH) and `30a2` (P2SH), Sapling HRP `ziwsapling`, and unified HRP `uziw`. These are lab network encodings. The upstream Ironwood protocol itself retains Orchard-protocol address structure. Define the lab viewing, spending, extended-key and WIF encodings before enabling their import/export. Reject unassigned or foreign encodings. Exercise decoding, signing and scanning against cross-network fixtures.
